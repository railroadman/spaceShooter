# План: тестовая среда эмуляции баланса (`plans/balance_alignment.md`)

## Контекст

Баланс (скорострельность, урон, спавн врагов, дроп, босс, стадии сложности) сейчас настраивается вручную игрой. Нужна среда, которая сама проходит игру ботом на ускоренном времени, много раз с разными seed, собирает метрики и позволяет менять параметры `config.js` на лету и сравнивать результаты.

## Решения (согласованы с пользователем)

- Запускается **настоящая игра** (`GameScene`) + бот-игрок, ускоренно. Логика не переписывается.
- Параметры: **панель на странице + JSON-пресеты**.
- **Жёсткое правило: песочница не затрагивает текущий код.** Ни один существующий файл не изменяется (ни `src/`, ни `index.html`, ни `assets/`, ни `config.js`, ни документация, ни `plan.md`/`CHANGELOG.md`/`CLAUDE.md`). Всё новое — только в новой папке `sandbox/balance/` (HTML, JS, пресеты, README). Игра импортируется оттуда как есть, только читается.

## Факты о коде (из исследования)

- `config.js` — чистые данные, без Phaser. Экспорты `WEAPONS`, `DROP`, `PICKUPS`, `SHIELD`, `DIFFICULTY`, `BOSS`, `ENEMY_WEAPONS` — изменяемые объекты; `PLAYER_HEALTH`, `PLAYER_LIVES`, `ENEMY_*_HEALTH` и т.п. — **примитивы** (нельзя менять в рантайме).
- Время: нет настенных часов, все компоненты копят `dt` из `Scenes.Events.UPDATE`; пули — на `WORLD_STEP`; `scene.time.delayedCall` идёт по часам сцены. Значит, ручной вызов `game.step(time, delta)` с фиксированным `delta` детерминирован и ускоряем.
- Случайность: только `Phaser.Math.RND` (сидируется `RND.sow`). `Math.random` в геймплее нет.
- Ввод игрока: `KeyboardInputComponent` слушает `scene.input.keyboard` `keydown/keyup` по `event.code` (стрелки/WASD/Space). Бот может эмулировать клавиши событиями без правок `Player`.
- Конец прогона: `BOSS_DEFEATED` (победа) или `GAME_OVER` (нет жизней). Жизни и счёт живут в `Lives` / `Score` (UI-объекты).
- Файлы с `window.Phaser` → Node не подходит, нужен браузер.

## Архитектура

```
sandbox/balance/
  index.html              панель: настройки, запуск пачки, таблицы/графики, пресеты
  run.html                одна изолированная игра (iframe), `?render=1` — показать игру на обычной скорости
  README.md               запуск и описание песочницы
  sim-panel.js            UI панели (список параметров, sweep, результаты)
  sim-orchestrator.js     очередь прогонов, N seed × сценарии, параллельные iframe
  run.js                  boot одной игры: import map, seed, цикл game.step, сбор метрик, postMessage
  config-patcher.js       патч config.js (примитивы + объекты) -> blob URL для import map
  bot-driver.js           бот-игрок (эмуляция клавиш)
  bot-profiles.js         профили навыка (данные)
  metrics-collector.js    подписка на EventBus + опрос состояния раз в секунду
  stats.js                агрегаты: медиана, p10/p90, win-rate, гистограммы
  targets.js              проверка целевых показателей (pass/fail)
  presets/                *.json: baseline, sweeps, цели
```

### Подмена `config.js` без правки игры

Игровые модули импортируют `./config.js`. `sandbox/balance/run.html` перед загрузкой модулей строит `<script type="importmap">`, который отображает URL `src/config.js` на blob с **пропатченным текстом**: `config-patcher.js` читает `config.js` как текст, для путей вида `PLAYER_HEALTH`, `WEAPONS.types.plasma.base.interval` подставляет значения (регэксп для примитивов `export const X = ...;`, для вложенных — deep-merge поверх объекта в конце модуля: `Object.assign`/`deepMerge(WEAPONS, overrides.WEAPONS)`). Один прогон = один iframe = одна конфигурация, поэтому перезагрузка модулей не нужна.

### Ускорение и детерминизм

- `new Phaser.Game({ type: HEADLESS | AUTO, audio: { noAudio: true }, ... })`, `game.loop` останавливается, цикл: `game.step(t, 16.667)` пока не конец / лимит игрового времени. Без рендера скорость ограничена только CPU (цель: полное прохождение 5–6 мин игрового времени за секунды).
- Перед `create` — `Phaser.Math.RND.sow([seed])`. Один seed = один воспроизводимый прогон.
- Риск (проверить спайком): HEADLESS и загрузка текстур/атласов; если не работает — `AUTO` с отключённым `renderer.render` (пустой draw) либо скрытый canvas.
- Паузы/сцены `LevelEndScene`/`GameOverScene` не нужны: прогон завершается по событиям, результат уходит `postMessage` родителю.

### Бот-игрок (`bot-driver.js`)

Эмулирует нажатия: `scene.input.keyboard.emit('keydown'|'keyup', {code})` (проверить сигнатуру в `keyboard-input-component.js`). Каждый кадр:
1. Берёт из сцены врагов, пули врагов, пикапы, босса (поиск по `scene.children` / группам по имени класса).
2. Угроза: сетка/потенциальное поле — оценка опасности клеток вокруг корабля с упреждением по скорости пуль; выбирает лучшее направление.
3. Цель: встаёт по X под ближайшего врага (для дробовика — ближе, для лазера — на линии); `Space` зажат всегда.
4. Пикапы: летит к ним, если риск ниже порога (`pickupGreed`).
5. Босс: держится под ним, избегает кольцо/веер.

Профили (`bot-profiles.js`, данные): `idle` (стоит и стреляет — базовый DPS/TTK), `novice` (задержка реакции 350 мс, шум прицела, радиус уклонения мал), `average`, `expert`; параметры: `reactionMs`, `aimNoise`, `dodgeRadius`, `pickupGreed`, `lookahead`. Это «шкала сложности» — баланс настраивается так, чтобы разные профили давали ожидаемый результат.

### Метрики (`metrics-collector.js`)

События берутся из `EventBus` сцены (имена уточнить в `event-bus-component.js`/`game-scene.js`), плюс опрос раз в игровую секунду.
Итог прогона: исход (win / dead / timeout), время до смерти/победы, счёт, потерянные жизни, урон по игроку по источникам (scout/fighter/boss/тип пули), убийства по типам, дропы по видам и подборы, таймлайн уровня оружия, время по стадиям `DIFFICULTY`, время появления и убийства босса (TTK), выстрелы/попадания, пик одновременных врагов.
Таймлайн (для графика): HP, жизни, DPS по окну 5 с, число врагов.

### Агрегация и цели

- `stats.js`: по N seed — win-rate, медиана/p10/p90 времени жизни, среднее потерянных жизней, распределение исходов, доля смертей по стадиям и от каких источников.
- `targets.js` + `presets/targets.json`: цели вида «`average`: win-rate 40–60%», «босс убивается за 40–70 с при weapon lvl ≥2», «смерть в стадии 1 < 5%», «дроп оружия ≥ 1 за 60 с». Панель показывает pass/fail и в какую сторону отклонение.

### Панель (`sandbox/balance/index.html`)

- Дерево параметров из `config.js` (группы: Игрок, Оружие, Враги, Спавн, Сложность, Дроп, Щит, Босс); поиск; поле значения + индикатор «изменено».
- Сценарий: профиль бота, N seed (по умолчанию 20), старт seed, лимит игрового времени, параллельность (iframe-ов), `DIFFICULTY.debug.startAt`, `BOSS.debug.spawnAt`, `DROP.debug.forceAll`, стартовое оружие (`WEAPONS.debug`).
- Sweep: путь параметра, от/до/шаг (до 2 параметров, сетка); результат — таблица и тепловая карта win-rate.
- A/B: baseline против текущих правок, дельты по метрикам, одинаковые seed.
- Результаты: сводка, гистограммы, таймлайн выбранного прогона, список прогонов с ссылкой «повторить с визуализацией» (`run.html?render=1` с тем же seed и конфигурацией, не ускоренно).
- Пресеты: сохранить/загрузить JSON (только отличия от baseline), экспорт результатов в JSON/CSV, «Export diff» — текстовый патч значений для ручного переноса в `config.js` (браузер сам файлы не пишет).

## Риски и допущения

- Детерминизм: нужен одинаковый `delta` и порядок вызовов; `Math.random` в косметике (частицы босса, молния) не влияет на геймплей. Проверка: два прогона одного seed дают равные метрики.
- HEADLESS может не поддерживать загрузку атласов/анимаций — запасной вариант описан выше.
- Правка примитивов регэкспом хрупка к форматированию `config.js`; патчер падает с понятной ошибкой, если `export const X` не найден.
- Бот не равен человеку; цель — относительные сравнения «до/после» и шкала профилей, а не точный прогноз.
- Игровой код не трогаем вообще. Если бот не сможет получить объекты сцены (приватные поля), доступ берём снаружи (обход `scene.children`, подписка на события, обёртки в `run.js` над методами созданных объектов), но не правками игры. Если без правки не обойтись — останавливаемся и спрашиваем.
- Новые файлы в `sandbox/balance/` создаются с CRLF (пользовательское правило).
